# 计划：动态 Skip Video DiT + Execution Horizon

> 状态（2026-09-11）：主线重新对齐——**先 cpp=1 适配训，再正式锚点扫**；旧 skip_v2 / success-BC 诊断线暂停。  
> 暂停说明：`docs/SKIP_ADAPT_PAUSE_NOTES.md`；四组旧结果：`docs/FOUR_WAY_EVAL_SNAPSHOT.md`。  
> 近期两件事的定案见 **§4.2a / §4.2b**。

---

## 1. 要解决什么问题

在 **World Action Model / VLA（AHA-WAM）** 闭环里，一次推理会预测一段 action chunk，并周期性调用 **Video DiT** 做视觉条件（prefill）。存在两类调度问题：

1. **是否调用 Video DiT（skip）**：少调用 → 省算力，但视觉更 stale，成功率可能掉。  
2. **执行多长再重新规划（execution horizon \(H_e\)）**：执行太长 → open-loop 盲区大；太短 → 推理次数多、可能抖动。

本计划：**固定其余超参，只学习上述两维调度**；并让动作主干在新调度模式下适度适应。

---

## 2. 术语（必须分清）

| 符号 | 名称 | 含义 | 本计划 |
|---|---|---|---|
| \(H_p\) | Prediction / action horizon（预测长度） | 一次 policy **预测**未来多少个 action | **固定**（如 64）；不做在线动态改输出维 |
| \(H_e\) | Execution horizon（执行长度） | 预测 chunk 中 **实际连续执行**多少步后重新观察/推理 | **在线学习**，\(H_e \le H_p\) |
| cpp | chunks_per_video_prefill | 隔多少个 action chunk 才考虑刷新 Video DiT | **固定为 1**；不学 |

文献里（DEHP / VLA-Corrector / Knowing When to Stop）**机制上调的都是执行侧截断 / 何时重规划**；标题有时写成 “action horizon”，易与 \(H_p\) 混淆。我们对外主术语用 **execution horizon \(H_e\)**，related work 中注明对应关系。

---

## 3. 已确定设定

### 3.1 固定项

- **cpp = 1**  
  - 与常见 WAM 设定一致；  
  - 保证整局有足够多次 Video DiT 决策点，skip 才有统计意义；  
  - cpp=2/4 时 prefill 次数过少，再 skip 空间窄，且与 skip 难解耦。  
- **\(H_p\) 固定**（默认与现网一致，如 **ah=64**；可用离线消融，不当在线动作空间）。  
- **不学动态 cpp**。

### 3.2 学习项

每次决策点（在 cpp=1 下 ≈ 每次 replan / chunk 边界）大致流程：

```text
obs
  → skip?  若否：跑 Video DiT prefill；若是：复用上次视觉条件
  → Action / WAM 预测 chunk a[1:Hp]   （Hp 固定）
  → He head 选 h ∈ H，执行 a[1:h]，丢弃其余
  → 下一决策点
```

要学的调度输出：

1. **skip ∈ {0,1}**：本次是否跳过 Video DiT；  
2. **\(H_e\)**：执行多长（建议先用离散档，如 `{8,16,32,64}`，再视情况加密）。

### 3.3 与当前 MAIN / 评测锚点的关系

- 历史 MAIN-2 / 正在跑的评测多锚在 **ah=64、cpp=2**。  
- 本计划主锚改为 **cpp=1** 后：与旧表对比须标明设定变更，或另附 cpp=2 对照列；  
- 在 cpp=1 下的 skip/\(H_e\) 训练与评测，不要和「cpp=2 上训的 skip_v2」无比，除非重训/重评对齐。

## 4. 训练方案（谁训、怎么训）

### 4.1 模块分工

| 模块 | 策略 | 理由 |
|---|---|---|
| Video DiT（视觉 / 世界侧） | **多数冻结**或极小 lr | 贵；skip 时经常不跑；猛训收益差 |
| Action 主干 | **联合轻量 FT**（小 lr） | 调度变了（更 stale、变长 open-loop）需要身子适应，纯冻易不衔接 |
| skip + \(H_e\) 头 | **正常训练** | 本计划核心「调度 policy」 |

对外可称 **一个系统 / 一个 policy**；实现上是 **可轻 FT 的 WAM/VLA + 调度头**，不是从零再训完整 WAM，也不是两个无关模型。

可选底座：现有 **skip_v2 offline FT**（在固定 skip 日程下适配动作）→ 再在此 ckpt 上加调度头。

### 4.2 推荐阶段（由稳到难）

1. **cpp=1 适配 FT**（§4.2a）→ 得到「习惯密 prefill 网格」的底座。  
2. **正式锚点扫**（§4.2b）：在 **适配后 ckpt** 上扫 cpp=1 × \(H_e\) × {always / FSM / random}。  
3. **调度 BC 预热**：FSM / 阶段启发式 / 成功轨伪标签 → skip 与 \(H_e\) 头。  
4. **Online RL**：调度头为主 ± Action 轻更；稀疏成功奖励；可选 \(-\lambda\cdot\#\)Video DiT。  
5. **消融**：只 skip / 只 \(H_e\) / 联合。

不优先：全参 RL 端到端重训整网；动态 cpp；为 cpp=1 另训/另找整网 WAM。

**顺序定案：正式锚点在训完之后。**  
若 16 卡有空，可用 **released** 做小规模探针扫（子集任务），**不写入主表**；主表只认适配后 ckpt，避免「权重未适配」和「日程效果」搅在一起。

### 4.2a 方案 A — cpp=1 适配训（底座）【定案：路径 3】

#### 选哪条路

| 路径 | 做法 | 结论 |
|---|---|---|
| 1 | 换帧当 `chunk_obs` + 只训 Action | 便宜；**≠** 评测 DiT+KV（已否决为主方案） |
| 2 | 换帧 + Video 也解冻 | 仍是换帧近似，不推荐 |
| **3（定案）** | **训练 forward 真跑 Video DiT，按 cpp=1 写/用 KV，再 Action BC** | 离线把主链路打通，最贴 always-cpp=1 部署 |
| 4 | 闭环仿真训 | 更真、更贵；A 之后 / RL 阶段再上 |

#### 路径 3 在训什么（机制）

目标：训练计算图贴近 deploy：

```text
对窗口内每个 action chunk（cpp=1 → 每 chunk 一次）：
  取该 chunk 起点附近的观测
  → 真跑 Video DiT prefill，写入 / 刷新 video KV
  → Action 在该 KV 条件下做 BC（demo 动作）
下一 chunk：再次 prefill（always，不 reuse）→ 新 KV → 再 BC
```

要点：

- **打通 = forward 走真 DiT + KV**，不是只换一张图进 OVCR。  
- **权重**：默认 **Video 冻或极小 lr，Action 主更新**（「打通」≠ 必须整网大 lr 狂训 Video；解冻 Video 是可选项，第一枪不默认开）。  
- **第一枪**：纯 cpp=1 always；不加随机 skip。  
- **仍不是闭环**：没有「执行→环境变→再观察」；比换帧真，比路径 4 假。  
- **验收**：ah64/cpp1 always 复评相对 released@cpp1 回升；抽查 cpp2 不崩。

与现有 skip_v2 训练差异：skip_v2 仍是 **换帧进 obs_context**；路径 3 要新做/改成 **类 `prefill_video` 的 KV 日程**（工程量大于改 yaml）。

### 4.2b 方案 B — 锚点扫（正式表）

| 项 | 定案 |
|---|---|
| 权重 | **默认 = §4.2a 训完 ckpt**（正式表）；released 仅可选探针 |
| 固定 | cpp=**1**，\(H_p\)=64（与计划主锚一致） |
| 扫描格 | \(H_e \in \{8,16,32,64\}\)（可先少档）× 模式 ∈ {**always prefill** / **FSM skip** / **random skip**} |
| 指标 | SR、Video DiT **calls/ep**、prefill_s/ep、success-per-call；L_chunk 作辅 |
| 任务 | 先子集（受益/受害各半）再扩；有 modeset 优先，避免 lavapipe 当事后主结论 |
| 资源 | 训完后用 **8–16 卡** 扫；若与训并行，只跑 released **探针** |
| 用途 | 判断 cpp=1 上是否有 skip 空间、FSM vs random、\(H_e\) Pareto → 决定 BC/RL 是否值得开 |

### 4.3 奖励（RL 阶段）

- 主项：任务成功；  
- 可选：惩罚 Video DiT 次数；  
- 不把 cpp 放进动作空间，不为 cpp 单独塑形。

### 4.4 环境与成本

- 调度 RL / 闭环适配依赖 **在线仿真**（RoboTwin）；  
- 当前乌兰训练容器常 **无可用 `/dev/nvidia-modeset`** → 只能 lavapipe，采样极慢；长期应推动平台注入 graphics，或在有 NVIDIA Vulkan 的环境上做 RL。  
- 探针入口：`train_probe_vulkan.sh`（`infra/` / 算法包）。

## 5. 和文献的对齐方式

| 工作 | 我们借用什么 |
|---|---|
| **DEHP** | 冻（或近冻）base chunk policy；学 \(H_e\)；chunk-level PPO + 稀疏成功奖励 |
| **VLA-Corrector** | 固定 \(H_e\) sweep 的 Pareto；执行中不可靠则截断（我们可用头学习代替纯规则） |
| **Knowing When to Stop** | 内部信号辅助截断的启发（可选；非必须依赖 attention entropy） |
| **本工作相对增量** | 在 WAM 上同时学 **skip Video DiT + \(H_e\)**；**cpp 固定为 1**；Action 轻联合适配 |
